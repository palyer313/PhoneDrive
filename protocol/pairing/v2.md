# 配对 v2 / PhoneDrive 0.2.1

传输使用 HTTPS，二维码携带服务端 RSA Host Key 的 SSH SHA256 指纹。TLS 证书的 RSA 公钥必须与该指纹一致，不依赖系统 CA 信任。手动输入也必须提供可信的完整指纹；禁止跳过验证或退回明文 v1。

二维码字段为 `v:2,ip,port,code,deviceid,name,type,fp`。Windows 邀请使用选定本机 IPv4 与动态端口，Android 邀请使用应用配置的配对端口（默认 47821）。有效期 120 秒，六位随机配对码连续错误三次作废，成功或关闭邀请后停止监听。

`GET /info` 返回 `v,deviceid,name,type,fp,nonce,sftpport`。客户端校验与扫码/手输的预期身份一致；nonce 由服务端为本次邀请随机生成。

`POST /pair` 请求字段为 `v:2,nonce,code,deviceid,name,type,hostFp,hostPub,clientPub,hostProof,clientProof`。

两个 proof 分别以对应私钥对以下 UTF-8 文本做 RSA SHA256 PKCS1 签名，输出 Base64（各行之间为 LF，最后无换行）：

```
PhoneDrive-Pair-v2
{nonce}
{deviceid}
{name}
{type}
{hostFp}
{hostPub}
{clientPub}
```

校验必须同时满足配对码、nonce、双方密钥签名、Host Key 与 hostFp 对应以及发起端本地用户批准。批准前不保存对端授权。错误码、旧 nonce、替换任一公钥必须失败。

成功响应为 `ok:true,v:2,nonce,deviceid,name,type,hostFp,hostPub,clientPub`，通过已固定服务端身份的 TLS 返回，客户端再次核对 nonce、指纹、公钥和设备身份。双方保存配对记录；作为文件服务端的一方保存对端 clientPub 到 authorized_keys。

Windows 目前仅作为控制端，`type:windows,sftpport:0`，手机不得把它作为可浏览文件源；Windows 保存手机的 SFTP Host Key，连接手机服务（默认 2222）。手机保存 Windows clientPub 授权其连接本机共享服务。新扫码配对后，Windows 允许最多 20 秒的认证重试，等待手机收到响应并保存授权；Host Key 不匹配始终立即拒绝。

自动重连和 SSHFS 挂载仍强制核对保存的 Host Key。二维码仅简化首次身份交换，不取消后续校验。身份变化需要重新配对。
